How many terms to compute e?

Add 1 + 1 + 1/2 + 1/6 + 1/24 + ... and after ten terms you have the number e to six decimal places. The famous recipe (1 + 1/n)^n needs n in the millions to do as well.

Name ____________________Date ____________

Tonight's idea

Some numbers have decimals that never end and never repeat, so nobody can write them out in full. You need a recipe that gets as close as you like. Tonight's number is called \(e\). It starts \(2.718281828\ldots\) and it turns up wherever something grows in proportion to its own size.

Recipe one. Write \(k!\) (say "\(k\) factorial") for \(1 \times 2 \times \cdots \times k\), and agree that \(0! = 1\). Then add \(\tfrac1{0!} + \tfrac1{1!} + \tfrac1{2!} + \tfrac1{3!} + \tfrac1{4!} + \cdots\), which is \(1 + 1 + \tfrac12 + \tfrac16 + \tfrac1{24} + \cdots\)

Recipe two. Work out \(\left(1 + \tfrac1n\right)^n\) for a large whole number \(n\).

Both close in on the same number \(e\), a fact proved in later courses. Tonight you measure how fast each one gets there.

Ten terms of the sum land within 0.0000005 of \(e\). The power \(\left(1 + \frac1n\right)^n\) needs \(n\) above 2.7 million to do as well.

Programmers hunt for recipes like the first: a little more work buys a lot more accuracy.

Watch one: seven terms of the sum

Each term is the one before it divided by the next whole number: \(\tfrac1{4!} = \tfrac1{3!} \div 4\). The error is \(e = 2.718281828\) minus the sum so far. Everything is rounded to five decimal places.

Your turn

  1. Carry the table on. (a) Work out \(7!\) and \(8!\). (b) Find \(\tfrac1{7!}\) and \(\tfrac1{8!}\) to seven decimal places and add them, one at a time, to the more accurate sum \(2.7180556\). (c) Find the error after each, using \(e = 2.7182818\).
  2. Call a value correct to six decimal places when its error is below 0.0000005. (a) The sum up to \(\tfrac1{8!}\) is \(2.71827877\). Add \(\tfrac1{9!}\), to eight decimal places. (b) Use \(e = 2.71828183\) to find the error before and after. Which sum is correct to six decimal places? (c) Count the terms used, starting from \(\tfrac1{0!}\).
  3. Now recipe two, on a calculator. (a) Work out \(\left(1 + \tfrac1n\right)^n\) for \(n = 10\), \(100\) and \(1000\), to five decimal places. (b) Find the error of each, using \(e = 2.71828\). (c) When \(n\) gets ten times bigger, roughly what happens to the error?
  4. For large \(n\), the error of \(\left(1 + \tfrac1n\right)^n\) is close to \(\tfrac{e}{2n}\). This is an approximation, not an exact formula. (a) Work out \(\tfrac{e}{2n}\) for \(n = 10\), \(100\) and \(1000\) and compare with exercise 3. (b) Estimate how large \(n\) must be for the error to drop below 0.0000005. (c) One more correct decimal place: what does it cost recipe two, and what does it cost recipe one near the tenth term?

Stretch: a guarantee that does not need e

So far you measured each error with a value of \(e\) that somebody else computed. Now do without. Stop the sum after \(\tfrac1{n!}\), with \(n \ge 1\). The part left out is the tail \(\tfrac1{(n+1)!} + \tfrac1{(n+2)!} + \tfrac1{(n+3)!} + \cdots\) Show that the tail is less than \(\tfrac{1}{n! \times n}\), then try \(n = 9\). Hints: put \(r = \tfrac1{n+1}\). Why is the second term of the tail less than \(r\) times the first, and the third less than \(r^2\) times the first? Then use \(1 + r + r^2 + r^3 + \cdots = \tfrac{1}{1 - r}\), true when \(0 \lt r \lt 1\).

Answers

  1. (a) \(7! = 720 \times 7 = 5040\) and \(8! = 5040 \times 8 = 40320\). (b) \(\tfrac1{5040} = 0.0001984\), so the sum becomes \(2.7180556 + 0.0001984 = 2.7182540\). Then \(\tfrac1{40320} = 0.0000248\), and the sum becomes \(2.7182788\). (c) The errors are \(2.7182818 - 2.7182540 = 0.0000278\) and \(2.7182818 - 2.7182788 = 0.0000030\). The last digit of each is not safe, because every number here was rounded: with more digits kept the errors are 0.00002786 and 0.00000306. Either way, one extra term cut the error about 9 times.
  2. (a) \(9! = 40320 \times 9 = 362880\) and \(\tfrac1{362880} = 0.00000276\). The sum becomes \(2.71827877 + 0.00000276 = 2.71828153\). (b) Before, the error was \(2.71828183 - 2.71827877 = 0.00000306\), which is too big. After, it is \(2.71828183 - 2.71828153 = 0.00000030\), which is below 0.0000005. So only the new sum is correct to six decimal places. (c) The terms run from \(\tfrac1{0!}\) to \(\tfrac1{9!}\), which is ten terms. With the trick from the example, that is at most nine divisions and nine additions.
  3. (a) \(1.1^{10} = 2.59374\), \(1.01^{100} = 2.70481\) and \(1.001^{1000} = 2.71692\). (b) The errors are \(0.12454\), \(0.01347\) and \(0.00136\). (c) The error becomes roughly ten times smaller. So ten times the \(n\) buys only about one more correct decimal place. Even \(n = 1000\) gives just \(2.717\), where seven terms of the sum gave \(2.71806\).
  4. (a) \(\tfrac{e}{20} = 0.13591\), \(\tfrac{e}{200} = 0.01359\) and \(\tfrac{e}{2000} = 0.00136\). The first is about 9% too big, the second about 1% too big, and the third agrees with your error to five decimal places. The approximation improves as \(n\) grows. (b) You need \(\dfrac{e}{2n} \lt 0.0000005\), so \(n \gt \dfrac{e}{0.000001} \approx 2{,}718{,}000\). That is about 2.7 million. A computer search with many digits agrees: the first \(n\) that works is 2,718,281. (c) Recipe two needs about 10 times more \(n\) for each extra place. Recipe one needs about one more term: the term \(\tfrac1{10!}\) cuts the error from \(0.00000030\) to \(0.00000003\). A warning about recipe two: the calculator must round \(1 + \tfrac1n\), and the huge power magnifies that rounding. A model calculator that keeps ten significant digits stores \(1 + \tfrac{1}{3{,}000{,}000}\) as \(1.000000333\), and that number to the power 3,000,000 is \(2.7156\), wrong in the third decimal place.

Stretch. The first term of the tail is \(\tfrac1{(n+1)!}\). The second is \(\tfrac1{(n+2)!} = \tfrac1{(n+1)!} \times \tfrac1{n+2}\), and \(\tfrac1{n+2} \lt \tfrac1{n+1} = r\). The third divides again, by \(n + 3\), so it is less than \(r^2\) times the first, and so on. So the tail is less than \(\tfrac1{(n+1)!}\left(1 + r + r^2 + \cdots\right)\). With \(r = \tfrac1{n+1}\) you get \(1 - r = \tfrac{n}{n+1}\), so the bracket is \(\tfrac{n+1}{n}\). Since \((n+1)! = n! \times (n+1)\), the bound is \(\dfrac{1}{n! \times (n+1)} \times \dfrac{n+1}{n} = \dfrac{1}{n! \times n}\). For \(n = 9\) that is \(\tfrac{1}{362880 \times 9} = \tfrac{1}{3265920} = 0.000000306\), which is below 0.0000005. So ten terms are guaranteed correct to six decimal places, and you never needed to know \(e\) in advance. The true error, 0.000000303, sits just under the bound. For \(n = 8\) the bound is 0.0000031, too big to promise six places, and exercise 2 showed that nine terms really do fall short. (The rule needs \(n \ge 1\): for \(n = 0\) it would divide by zero.)
